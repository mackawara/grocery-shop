# WhatsApp catalog feed — API specification

Status: implemented locally; not deployed. MongoDB remains the source of truth.

## Decision

Each tenant owns one Meta catalog connected to its own WhatsApp Business Account (WABA). Meta
periodically fetches a complete CSV feed generated by this API. Product writes do not call Meta and
do not depend on Meta being available.

This is the selected simpler alternative to per-write Graph API pushes. Meta's scheduled-feed
documentation says scheduled fetches cannot run more frequently than hourly. A complete `schedule`
refresh creates and updates rows and deletes catalog items missing from the feed. An
`update_schedule` is incremental and must not be used alone because it will not implement product
deletion.

Official references:

- [WhatsApp catalogs overview](https://developers.facebook.com/documentation/business-messaging/whatsapp/catalogs/catalogs-overview)
- [Upload inventory to Meta](https://developers.facebook.com/documentation/business-messaging/whatsapp/catalogs/upload-inventory)
- [Schedule data feed uploads](https://developers.facebook.com/documentation/ads-commerce/catalog/guides/scheduled-feeds)
- [Catalog fields and supported feed formats](https://developers.facebook.com/documentation/ads-commerce/commerce-platform/catalog/fields)

## Public endpoints consumed by Meta and customers

### `GET /catalogs/:tenantSlug/products.csv`

Returns a UTF-8 CSV complete feed for exactly one active/trial tenant.

- Tenant resolution is the only cross-tenant operation and uses the logged `runWithoutTenant`
  escape hatch.
- The product query runs inside `runWithTenant` and through the `tenantScope`-plugged `Product`
  model.
- Only `ACTIVE` products are exported.
- `DRAFT` and `ARCHIVED` products are absent.
- An active legacy product missing a required Meta field is omitted and logged; it does not break
  every other item in the feed.
- Out-of-stock products remain in the feed with `availability=out of stock`.
- The response is public because the catalog fields are customer-visible commerce data. Drafts,
  tenant credentials, customer data, orders, and internal sync metadata are never returned.

Production feed URL:

```text
${PUBLIC_BASE_URL}/catalogs/{tenantSlug}/products.csv
```

### `GET /catalogs/:tenantSlug/products/:sku`

Returns a small public HTML landing page for one active product. Every CSV `link` points to this
exact product URL. This replaces the previous `facebookPageUrl` fallback, which does not meet
Meta's current requirement that `link` identify the specific item and not point to a Facebook
domain.

## Dashboard product write API

All write endpoints require a valid dashboard session, tenant context, and `VENDOR` or
`SHOP_MANAGER` role.

| Method  | Endpoint                               | Effect in MongoDB                                       | Effect after Meta's next complete refresh |
| ------- | -------------------------------------- | ------------------------------------------------------- | ----------------------------------------- |
| `POST`  | `/dashboard/products`                  | Creates a draft or active product                       | Active product is created/updated in Meta |
| `PATCH` | `/dashboard/products/:id`              | Updates product fields                                  | Active row is updated                     |
| `POST`  | `/dashboard/products/:id/publish`      | Sets `status=active` after readiness validation         | Row appears                               |
| `POST`  | `/dashboard/products/:id/archive`      | Sets `status=archived`                                  | Missing row is removed                    |
| `POST`  | `/dashboard/products/:id/out-of-stock` | Sets quantity to `0` and availability to `out_of_stock` | Row remains but is sold out               |

Any create/update with quantity `0` is normalized to `out_of_stock`. Increasing quantity does not
automatically restock an intentionally unavailable item; the vendor must explicitly choose
`in_stock`.

## Configure each tenant's Meta catalog

The Meta assets already exist, so configure one Product Feed in each tenant's catalog with the
tenant-specific URL above. Use a complete replacement `schedule`; hourly is the fastest supported
periodic interval. The same setup can be done in Commerce Manager or with the Graph API:

```bash
curl -X POST \
  -F 'name="Grocery Shop scheduled feed"' \
  -F 'schedule={"interval":"HOURLY","url":"https://api.example.com/catalogs/vendor-slug/products.csv"}' \
  -F 'access_token=<TENANT_CATALOG_ACCESS_TOKEN>' \
  'https://graph.facebook.com/v25.0/<TENANT_CATALOG_ID>/product_feeds'
```

Never store this token in the dashboard browser or include it in the feed URL. It is only needed
when configuring Meta; Meta subsequently fetches the public feed URL without the token.

## Required feed data

The API exports Meta's core required fields: `id` (tenant SKU), `title`, `description`,
`availability`, `condition`, `price`, exact product `link`, `image_link`, and `brand`. It also emits
the supported optional product, variant, sale-price, category, weight, stock-quantity, and custom
label fields already present in the Product model.

Images must remain publicly reachable over HTTPS and meet Meta's size/format rules. The existing
publish-readiness check blocks an active product without an image.

## Operational behavior

- Expected delay is the Meta schedule plus Meta processing time; the dashboard must not call a
  product "synced" immediately after saving it.
- Feed ingestion errors and item policy rejections are observed in Commerce Manager. A scheduled
  feed does not provide this API with per-item acknowledgements.
- This endpoint is a machine-facing Meta feed and preserves merchant text exactly. Do not reuse it
  as a human spreadsheet download; any future Excel/Sheets export must neutralize formula-leading
  cells separately so feed values are not altered.
- The legacy per-item Batch API controller has been removed. Its schema metadata remains temporarily
  for backwards-compatible reads of existing product rows, but scheduled-feed writes reset
  `syncStatus` to `NOT_SYNCED`; Commerce Manager is the source of feed-ingestion status.
- If private feed authentication becomes necessary, Meta supports Basic Auth for scheduled HTTP
  feeds. Adding it safely requires encrypted, rotatable, per-tenant credentials and a dashboard
  setup workflow; do not use a shared credential across tenants.

## Verification checklist

1. Deploy the API and verify the tenant URL returns `200` and `text/csv` over public HTTPS.
2. Open one emitted `link` and verify the exact active product page returns `200`.
3. Add the URL as a complete scheduled feed in the matching tenant's Meta catalog.
4. Create an active product and confirm it appears after the next refresh.
5. Mark it out of stock and confirm it remains visible as sold out.
6. Archive it and confirm the following complete refresh removes it.
7. Repeat with a second tenant and confirm neither feed contains the other's SKU or product data.
